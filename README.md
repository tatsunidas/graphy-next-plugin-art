# graphy-next-plugin-art

GRAPHY-Next の **Art of Imaging** プラグイン。表示中の DICOM 画像を、パブリックドメインの画家の作風による作品に翻案し、鑑賞のための説明を添えて出力します。

> 研究・教育・芸術表現のためのものです。**診断機器ではありません。**

> ### 🔴 GRAPHY-Next **0.3.0 以降**が必要です
> 外部 AI への送信（`host.ai`）・名前を付けて保存（`host.file`）・画面に見えている範囲
> （`getViewState().visibleRegion`）はいずれも **0.3.0 で入るホスト API** です。
> `plugin.json` の `engines.graphy` が `>=0.3.0` を宣言しているため、**それ未満の本体では
> 導入時に弾かれます**（`incompatible: plugin requires graphy >=0.3.0 but core is ...`）。

## 何をするか

1. 表示中スライスの校正済み画素に表示 W/L を掛けて 8-bit RGB に変換する
2. 様式と画家（1 名）からプロンプトを自動生成し、Gemini に画像を生成させる
3. 生成画像と同時に鑑賞説明（写っているもの／鑑賞のために）を受け取って並べて表示する
4. サイン（文字・位置・フォント・大きさ／**色は黒のみ**）を焼き込む
5. 名前を付けて保存する。PNG に `graphy-art` メタデータと画像ハッシュを埋め込む

> ⚠️ **現時点では、まだ動かせる GRAPHY-Next がありません。**
> このプラグインは本体の `host.ai`（外部 AI への送信）と `host.file`（名前を付けて保存）に
> 依存しますが、これらは **0.3.0 で入る予定**で未リリースです。
> コードの公開が先行しているのは、設計と実装を先に見られる状態にしておくためです。

## 必要なもの

- GRAPHY-Next **0.3.0 以降**（`host.ai` / `host.file` ホスト API が要る。**未リリース**）
- Gemini の API キー。本体の **環境設定 ＞ 外部 AI** で設定します。キーは OS のキーチェーンに預けられ、このプラグインからは読めません。

## 導入方法

> ⚠️ **いまは導入できません。** GRAPHY-Next 0.3.0 が未リリースのためです
> （`plugin.json` の `engines.graphy` が `>=0.3.0` で、本体が満たさない版では
> **導入時に弾かれます**）。以下は 0.3.0 公開後の手順です。

### 利用者（プラグインマネージャから）

1. GRAPHY-Next を起動し、**プラグイン ＞ プラグインマネージャ** を開く
2. このリポジトリの URL（`https://github.com/tatsunidas/graphy-next-plugin-art`）を入れる
3. 確認画面で、**同梱物・要求する権限・対応 OS・ハッシュ**を確認して同意する
4. 本体を開き直す（プラグインは起動時に読まれます）
5. **環境設定 ＞ 外部 AI** で Gemini の API キーを設定する
6. 2D ビューアで画像を開き、**解析 ＞ Art of Imaging**

要求する権限は 3 つです。確認画面にそのまま出ます。

| 権限 | 何に使うか |
|---|---|
| `read-pixels` | 表示中スライスの画素を読む |
| `ai-egress` | **画像を Google のクラウドへ送る**（送信ごとに本体が同意を求めます） |
| `file-save` | 作品を名前を付けて保存する |

### 開発者（ソースから）

```bash
git clone https://github.com/tatsunidas/graphy-next-plugin-art
cd graphy-next-plugin-art && npm install && npm run verify   # 型・テスト・ビルド
cp plugin.json ui.js <GRAPHY-Next>/desktop/plugins/art/      # 直接置く
```

`desktop/plugins/` 直下に置く経路はプラグインマネージャの検査（版数・OS・ハッシュ・署名）を
**通りません**。開発中だけに使ってください。

## 個人情報について

- 画像は第三者（Google）のクラウドへ送信されます。院内規程・倫理審査・患者同意の範囲内でのみ使用してください。
- 送信前に、**実際に送る画像とプロンプト全文**を示す同意ダイアログが本体側で出ます。必ず確認してください。
- 画素に焼き込まれた患者情報（バーンドイン注釈）は取り除かれません。
- 無料枠では入力が Google のモデル改善に利用され得ます。患者由来の画像は有料ティアで扱ってください。
- プロンプトに載る DICOM 由来の情報は **モダリティと部位の 2 つだけ**で、いずれも既定用語の一覧に一致した値のみです（`src/core/prompt.ts`）。

## 画家の収録方針

パブリックドメインの画家のみを収録しています。判定は単純な「没後 70 年」ではなく、日本の**戦時加算**（連合国民の 1941/12/7 以前の著作物に最大約 10 年 5 か月）を織り込んだ **没年 1944 年以前**です。`test/painters.test.ts` が全件を機械的に検査します。

画風・様式そのものは著作権の保護対象ではありません。プロンプトでも「特定作品の複製ではなく様式の翻案」であることを明示しています。

## 画家一覧のサムネイル

名前だけでは「その画家を選ぶと何が出てくるか」が分からないため、一覧には
代表作のサムネイルを並べています。

**画像は `ui.js` に base64 の data URI として焼き込んであります。** プラグインが
配信できるのは `plugin.json` と `ui.js` だけで（ホストの `PluginController` は
`/{id}/ui.js` しか返さない）、しかもホストの CSP は `img-src 'self' data: blob:`
なので、実行時に外部から画像を引くことはできません。取得は**開発時の一度きり**で、
プラグインは実行時にネットワークへ出ません。

収録しているのは**パブリックドメインと確認できた画像だけ**です。出所は 1 枚ごとに
[`THIRD-PARTY-IMAGES.md`](THIRD-PARTY-IMAGES.md) に画家・収録作品・取得元ファイル・
出典・ライセンス・URL を記録しています。

### 取り直し方

```bash
npm run thumbs     # tools/fetch-thumbs.py。Python 3 と Pillow が要る
git diff --stat src/core/thumbs.ts THIRD-PARTY-IMAGES.md
```

`src/core/thumbs.ts` と `THIRD-PARTY-IMAGES.md` は**生成物です。手で編集しないでください。**
`npm run verify` からは呼びません（検証にネットワーク依存を持ち込まないため）。
照合の規則だけは `npm run thumbs:check` でネットワーク無しに検査できます。
**実際に掴んだ誤りをそのまま検査例にしてある**ので、規則を緩めると落ちます。

取得スクリプトが守っていること:

- **パブリックドメインと確認できた画像しか採らない。** Met の `isPublicDomain` か
  Commons の `LicenseShortName` で判定し、読み取れないものは捨てます。MIT の
  リポジトリに CC BY-SA の写真を焼き込まないためです。
- **その画家の、その作品だけを採る。** 作品名の照合に加えて画家名を必ず確かめます。
  Commons の全文検索は画家名を無視して題名だけで当ててくるため、この検査が無いと
  「コンポジション VIII」でテオ・ファン・ドースブルフの絵が入ります。
- **習作・部分の切り抜き・他人による模写は採らない。** 「民衆を導く自由の女神」で
  人体の習作を、「雨、蒸気、速度」で後年の複製版画を掴んだ実例があります。
- **見つからなければ空のまま残す。** それらしい別の絵で埋めません。一覧では無地の枠に
  なります。取れなかった画家はスクリプトが最後に一覧で出します。

原語の題名でしか登録が無い作品（「抱擁」= *Umarmung* など）は照合では辿り着けません。
**照合を緩めるのではなく**、`tools/fetch-thumbs.py` の `MANUAL_FILES` に
ファイル名を名指しで書きます。名指ししたファイルもライセンスは同じように検査します。

### 収録作品はカタログの 1 点目とは限らない

1 点目のパブリックドメイン画像が見つからないと 2 点目に落ちるので、`thumbs.ts` は
**その画像が実際に何の絵なのか**（`workJa` / `workEn`）を一緒に持っています。
一覧のラベルは `painter.works[0]` ではなく必ずこちらを使ってください。
`test/thumbs.test.ts` が、収録作品がカタログに実在することを検査します。

## Art of GRAPHY へ投稿する

作った作品は **[Art of GRAPHY](https://vis-ionary.com/art-of-graphy/)** へ投稿できます。

| ページ | URL |
|---|---|
| ギャラリー | <https://vis-ionary.com/art-of-graphy/> |
| 投稿フォーム | <https://vis-ionary.com/art-of-graphy/upload/> |
| 投稿規約 | <https://vis-ionary.com/art-of-graphy/terms/> |
| ランキング | <https://vis-ionary.com/art-of-graphy/ranking/> |

### 🔴 書き出した PNG を加工しないでください

投稿されると、サーバ側が PNG の `graphy-art` メタデータを読み、**画素から SHA-256 と
pHash を数え直して**埋め込まれた値と突き合わせます。合わなければ受け付けられません。

画像編集ソフトで開いて保存し直すと、多くの場合メタデータが失われます。
**「名前を付けて保存」で出したファイルを、そのまま**アップロードしてください。

- リサイズ・トリミング・色調整をすると弾かれます
- 長辺 8192px 以下・短辺 256px 以上
- 同じ画像（および酷似した画像）は重複として弾かれます

### フォームに入れるもの

| 欄 | 必須 | 上限 | このプラグインでの入手先 |
|---|---|---|---|
| 作品ファイル（PNG） | ● | — | 「名前を付けて保存」で出したファイル |
| 作者名 | ● | 60 字 | ご自身で入力（ペンネーム可） |
| 作品タイトル | | 80 字 | **生成された「題名」をコピー**（省略すると自動で付きます） |
| 鑑賞のための説明 | ● | 800 字 | **生成された「鑑賞文」をコピー** |
| メールアドレス | ● | — | ご自身で入力 |

題名と鑑賞文は生成後にダイアログへ出ます。**それぞれのコピーボタン**でそのまま貼り付けられる
よう、上限をフォームに合わせてあります（`src/core/prompt.ts` の `TITLE_MAX_CHARS` / `NOTE_MAX_CHARS`）。

**画家名・作風・モダリティは入力しません。** 投稿先が PNG のメタデータから自動で表示するため、
鑑賞文では意図的に触れないようプロンプトで指示しています。

### 投稿する前に

- 画素に焼き込まれた患者情報が**残っていないか**を必ず確認してください。
  プラグインは DICOM タグを送りませんが、**焼き込み文字は消しません**
  （本体の匿名化 ＞ ピクセル焼き込み除去で消せます）。
- 公開される作品です。所属規程・倫理審査・患者同意の範囲内でご判断ください。
- 詳しい条件は[投稿規約](https://vis-ionary.com/art-of-graphy/terms/)をご確認ください。

## 生成物の識別

PNG の `iTXt` チャンク（キーワード `graphy-art`）に生成情報を JSON で埋め込みます。

```json
{ "spec": "graphy-art/1", "generator": "GRAPHY-Next Art of Imaging",
  "model": "...", "style": {...}, "signature": {...},
  "source": { "modality": "CT", "bodyPart": "CHEST" },
  "prompt": "...", "sourceImageSha256": "...", "imageSha256": "...", "pHash": "..." }
```

`source` に患者識別子は入りません（UID も入れません）。

**メタデータは再エンコードで消えます。** 受け入れ側（Web サービス）は次の三層で判定してください。

| 層 | 用途 | 剥がされたとき |
|---|---|---|
| `graphy-art` メタデータ | GRAPHY 製である一次判定 | 消える |
| `pHash`（**サーバ側で再計算**して突合） | 重複登録の検知。ハミング距離 ≤ 5 を重複候補とする | 効く |
| `imageSha256`（生 RGBA の SHA-256） | 完全同一の検知 | 効く（再計算すれば） |

埋め込まれた値をそのまま信用して比較しないこと（書き換えるだけで回避できるため）。いずれも改ざん耐性はありません。

## ホスト API の型

本体から渡される API のうち**このプラグインが使うものだけ**を `src/hostTypes.ts` に宣言しています。
完全な定義は GRAPHY-Next の `examples/plugin-template/graphy-plugin.d.ts` を参照してください
（全体を写すと本体の更新のたびに差分が出て、使っていない箇所の食い違いに時間を取られるため）。

## 開発

```bash
npm install
npm run verify     # typecheck + test + build
npm run build      # ui.js を生成
npm run thumbs        # 画家一覧のサムネイルを取り直す（ネットワークを使う・手動）
npm run thumbs:check  # 取得スクリプトの照合規則だけを検査（ネットワーク不要）
```

配布は `plugin.json` と `ui.js` を含む zip を GitHub Release に置き、minisign で署名します。
